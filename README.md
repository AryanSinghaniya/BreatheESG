# Breathe ESG — Prototype

A small Django + Vite (React) prototype for enterprise ingestion and review workflows.

## Quick overview
- Backend: Django 5 (REST API), WhiteNoise for static serving.
- Frontend: Vite + React 18.
- Deploy target used in this repo: Render (blueprint in `render.yaml`).

This README covers local development, common deployment notes, and troubleshooting tips.

## Repository layout

- `backend/` — Django project (manage.py lives at repo root `backend/manage.py`).
- `frontend/` — Vite + React app.
- `render.yaml` — Render blueprint used to create two services (backend + frontend).
- `requirements.txt` — Python dependencies for production builds.

## Prerequisites

- Python 3.11 (recommended for Render binary compatibility).
- Node.js + npm (for frontend development).
- Optional: PostgreSQL if you want to run with Postgres locally.

## Local backend (development)

1. Create and activate a virtual environment:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1    # PowerShell on Windows
source .venv/bin/activate         # macOS / Linux
```

2. Install Python dependencies (uses `requirements.txt` in repo root):

```bash
python -m pip install -r requirements.txt
```

Note: On Windows you may see a build error for `psycopg2-binary` if `pg_config` isn't available. See Troubleshooting below.

3. Run migrations and start the dev server (SQLite default when `DATABASE_URL` not set):

```bash
cd backend
python manage.py migrate
python manage.py runserver 8000
# API available at http://127.0.0.1:8000/
```

## Local frontend (development)

1. Install and run the dev server:

```bash
cd frontend
npm install
npm run dev
# Open http://localhost:5173
```

2. Build and preview (this repo config binds preview to environment PORT for Render):

```bash
npm run build
# For local preview (default port 4173):
npm run preview
```

Notes about preview on Render
- `frontend/vite.config.js` uses a `preview` config that binds to `0.0.0.0` and uses `process.env.PORT || 4173` so Render can detect the open port.
- `preview.allowedHosts` includes the Render domain so Vite does not block the Host header.

## Deployment notes (Render)

- Use the supplied `render.yaml` blueprint to create two services: `breathe-backend` (Python) and `breathe-frontend` (Node).
- Ensure `runtime.txt` pins Python to a compatible 3.11.x version (we used `python-3.11.9`).
- For the backend service set env vars in Render (or via `render.yaml`):
  - `DJANGO_SECRET_KEY` (required)
  - `DJANGO_DEBUG=false`
  - `ALLOWED_HOSTS` (comma-separated hosts for production)
  - `CORS_ALLOWED_ORIGINS` (comma-separated, or use `CORS_ALLOW_ALL_ORIGINS=true` in dev only)
  - `DATABASE_URL` (pointing to a Postgres instance for production; remove DB creation from blueprint if you want to reuse an existing free-tier DB)
- Frontend: set `VITE_API_URL` to your backend public URL (for example `https://breathe-backend.onrender.com`).

## Troubleshooting

- psycopg2 / psycopg2-binary build errors on Windows:
  - If pip tries to build `psycopg2-binary` from source you will need `pg_config` (Postgres dev) or build tools installed. To avoid this while developing locally you can:
    - Use SQLite locally (the project defaults to SQLite when `DATABASE_URL` is not set), or
    - Install PostgreSQL and add its bin directory (containing `pg_config`) to your PATH, or
    - On Windows install the PostgreSQL client tools (or use WSL).

- Missing package errors (e.g., `No module named 'whitenoise'`):
  - Ensure you installed dependencies in the active virtualenv: `python -m pip install -r requirements.txt` or install specific package: `pip install whitenoise`.

- Vite preview `Blocked request. This host ... is not allowed`:
  - Add the Render domain to `preview.allowedHosts` in `frontend/vite.config.js` and bind preview to `0.0.0.0` and `process.env.PORT` (already configured in this repo).

- Render deploy shows "No open ports detected":
  - Ensure the frontend start command exposes the port Render expects. This repo uses `npm run start` which runs `vite preview --host 0.0.0.0 --port $PORT`.

# Breathe ESG Ingestion Prototype

Monorepo with a Django REST backend and a React (Vite) frontend.

## Local setup

### Backend

1. Create a virtual environment.
2. Install deps:
   - `pip install -r backend/requirements.txt`
3. Run migrations (SQLite is the default for local dev):
   - `python backend/manage.py migrate`
4. Start the server:
   - `python backend/manage.py runserver 8000`

Optional: set `DATABASE_URL` in backend/.env.example to use Postgres locally.

### Frontend

1. Install deps:
   - `cd frontend`
   - `npm install`
2. Start the dev server:
   - `npm run dev`

Use the UI button "Create default company" or POST to `/api/companies/`.

## API overview

- `GET /api/health/`
- `GET /api/companies/`
- `POST /api/companies/`
- `POST /api/ingest/` (multipart form with `company_id`, `source_type`, `file`)
- `GET /api/batches/`
- `GET /api/records/`
- `GET /api/records/{id}/detail/`
- `POST /api/records/{id}/approve/`
- `POST /api/records/{id}/reject/`
- `POST /api/records/{id}/lock/`
- `PATCH /api/records/{id}/`

## Render deployment

This repo includes a render.yaml blueprint. Create a new Render Blueprint service pointing at the repo.

1. Set backend env vars:
   - `DJANGO_SECRET_KEY`
   - `DJANGO_DEBUG=false`
   - `ALLOWED_HOSTS=<render-backend-host>`
   - `CORS_ALLOWED_ORIGINS=<render-frontend-url>`
2. For the frontend, set `VITE_API_URL` to the backend URL.

Note: Render deployment uses Postgres via `DATABASE_URL`. Local dev defaults to SQLite.
